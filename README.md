# أداة التحقق من تغطية ألياف موريتل (FTTH) — نواكشوط

أداة محلية: تلصق رابط Google Maps من العميل، فتستخرج الإحداثيات، وتعرض الموقع على الخريطة، وتقارنه بمضلعات التغطية المحفوظة في `data/coverage.geojson`.

## القاعدة الأساسية: لا تخمين
| النتيجة | متى تظهر |
|---|---|
| ✅ داخل التغطية | النقطة داخل مضلع علامته `verified: true` |
| ❌ خارج التغطية | خارج كل المضلعات **و** `complete: true` في ملف التغطية **و** يوجد مضلع موثوق واحد على الأقل |
| ❓ غير مؤكد | أي حالة أخرى: لا بيانات، أو مضلع «مسودة»، أو بيانات غير معلنة كاملة |

المضلعات المرسومة أو المستوردة تُحفظ كـ «مسودة» ولا تُحتسب حتى تعلّمها أنت «موثوق».

## التشغيل (يحتاج Node.js 18 أو أحدث، ولا يحتاج `npm install`)
```
cd mauritel-ftth-checker
npm start
```
ثم افتح `http://localhost:3000`. للاختبار: `npm test`.

## هيكل المشروع
```
server.js              الخادم المحلي: فك الروابط المختصرة + قراءة/حفظ البيانات
public/index.html      الواجهة
public/js/parse.js     استخراج الإحداثيات من الروابط
public/js/geo.js       منطق داخل/خارج/غير مؤكد
public/js/app.js       الخريطة والتحرير
data/coverage.geojson  حدود التغطية (121 منطقة من خريطة موريتل)
data/source/           الملف الأصلي zones_ftth.json
scripts/convert-zones.js  تحويل ملف موريتل إلى صيغة الأداة
data/pos.geojson       نقاط بيع موريتل
data/places.json       المواقع المحفوظة يدويًا (كود + حي + معلم)
data/locations.json    سجل المواقع المُرسلة (تلقائي)
data/zone-areas.json   اسم الحي لكل بادئة كود
data/backups/          نسخة احتياطية تلقائية قبل كل حفظ
test/                  الاختبارات
```

## بيانات التغطية الحالية
`data/coverage.geojson` فيه **121 منطقة** مأخوذة من ملف `zones_ftth.json` الذي تحمّله خريطة موريتل الرسمية (`/ftthZones/zones_ftth.json`)، وصُدّر بتاريخ 2026-10-12 (مكتوب داخل الملف في `exportedAt`). تشمل نواكشوط ومدنًا أخرى. الأصل محفوظ في `data/source/`.

كود الصفحة الرسمية يرسم كل منطقة في الملف بنفس التنسيق، وليس فيه حقل حالة، فاعتُبرت كل المناطق مناطق ألياف (`verified: true`). اختلاف التظليل في الخريطة الرسمية سببه تمرير الماوس فقط. «خارج التغطية» تعني خارج المناطق المنشورة، وقد لا تعكس توسعًا حديثًا بعد تاريخ التصدير.

### تحديث البيانات عند تغيّر خريطة موريتل
1. افتح `mauritel.mr/couveture/fibre` ثم F12 ← Network ← Fetch/XHR ← F5.
2. كليك يمين على `zones_ftth.json` ← Open in new tab ← Ctrl+S.
3. شغّل: `node scripts/convert-zones.js مسار/zones_ftth.json` (يحفظ نسخة احتياطية من القديم تلقائيًا).

### طرق أخرى (مدن أو مناطق ليست في الملف)
استيراد GeoJSON/KML من وضع التحرير، أو الرسم اليدوي بأداة المضلع. كل ما يُضاف هكذا يبقى «مسودة» حتى تعلّمه «موثوق».

## اسم الحي من Google Maps
كود المنطقة (مثل CA1Z02) يأتي من بيانات موريتل. **اسم الحي** يتركب من:
0. **بادئة الكود** حسب `data/zone-areas.json` (مثل CA = كرفور عرفات). عدّل هذا الملف وأضف بادئات الأحياء التي تعرفها (TZ، KT، SB...) ولا تضف إلا ما تتأكد منه.

ثم الاسم والمعلم القريب (مثل «قرب صيدلية ...») من المصادر التالية، بالترتيب:
1. **Google Maps (Geocoding API):** يعمل فقط إذا وضعت مفتاحًا في ملف `.env` (انسخ `.env.example` إلى `.env` واكتب `GOOGLE_MAPS_API_KEY=مفتاحك`). المفتاح يحتاج تفعيل «Geocoding API» وحسابًا في Google Cloud مع تفعيل الفوترة. يُحفظ على جهازك فقط ولا يصل للمتصفح، ولا تشاركه مع أحد.
2. **بدون مفتاح:** يُستخدم OpenStreetMap، وتُكتب العبارة «(لا يوجد مفتاح Google)» بجانب الاسم.
3. إن كان رابط العميل طويلًا ويحمل اسم مكان، يظهر في سطر «اسم المكان في الرابط».

## المواقع المحفوظة (كود + حي + معلم)
للعملاء اللي عندك عنوانهم بدون رابط: افتح «إضافة موقع جديد» واكتب كود المنطقة (مثل `DN2Z01`) والحي (دار النعيم) والمعلم (بوتيك جمبو)، ثم «حفظ». الكود لازم يكون موجودًا في بيانات موريتل، وإلا يُرفض (حماية من أخطاء الكتابة). تُحفظ في `data/places.json`.
بعدها اكتب في خانة «استدعاء موقع محفوظ» الكود أو الحي أو جزءًا من المعلم، وتظهر النتيجة مباشرة مع تظليل المنطقة على الخريطة.
خيار «اعتمد هذا الحي لكل مناطق نفس البادئة» يحفظ الحي في `data/zone-areas.json`، فتظهر كل مناطق DN بهذا الحي.
تنبيه: النتيجة هنا حسب الكود المُدخل فقط، ولا تتحقق من موقع العميل الدقيق.

## سجل المواقع المُرسلة (تلقائي)
كل موقع تلصقه كرابط أو إحداثيات يُحفظ تلقائيًا في `data/locations.json` مع: الإحداثيات، كود المنطقة، الحالة، الحي، المعلم، الرابط الأصلي، وتاريخ أول وآخر مرة. نفس الموقع لا يتكرر، بل يزيد عدّاده فقط. النقر على الخريطة أو البحث اليدوي لا يُسجَّل.
لاستعراضه: اضغط «بحث» في خانة «استدعاء موقع محفوظ» وهي فارغة لتظهر آخر 10 مواقع، أو اكتب كودًا أو حيًّا أو معلمًا.
**خصوصية:** مواقع العملاء بيانات شخصية، فهي على جهازك فقط وملف `.gitignore` يمنع رفعها على GitHub. لا ترسل مجلد `data` لأحد.

## التطوير لاحقًا
- **مناطق جديدة:** ارسمها أو استوردها (أي مدينة، لا نواكشوط فقط، لكن المستطيل في `parse.js` يخص نواكشوط وللتنبيه فقط).
- **نقاط البيع:** أداة الدبوس في وضع التحرير، وتُحفظ في `data/pos.geojson`. تظهر أقرب نقطة بيع للمعلومة فقط.
- **ملاحظات:** فك الروابط المختصرة يحتاج إنترنت على الجهاز. أسماء الأحياء تأتي من OpenStreetMap وقد لا تطابق تسميات موريتل. الخادم يستمع على `127.0.0.1` فقط.

## النشر على الإنترنت (GitHub + Vercel + Supabase)

محليًا يعمل كل شيء كما هو (ملفات في `data/`). عند النشر على Vercel لا يمكن الكتابة على الملفات،
لذلك تُحفظ **المواقع المُرسلة + المواقع اليدوية + أسماء الأحياء** في قاعدة Supabase،
ويكون الدخول بحساب (بريد + كلمة مرور) ومن قائمة مسموح بها فقط.
حدود التغطية (121 منطقة) تُقرأ من الملف المرفوع مع المشروع (قراءة فقط على النسخة المنشورة).

### 1) Supabase
1. أنشئ مشروعًا جديدًا في supabase.com.
2. SQL Editor ← الصق محتوى `supabase/schema.sql` ← Run.
3. Authentication ← Providers ← Email: عطّل **Allow new users to sign up** (لا تسمح بتسجيل الغرباء).
4. Authentication ← Users ← Add user: أنشئ حسابك (بريد + كلمة مرور) وأكّد البريد (Auto Confirm).
5. Project Settings ← API: انسخ `Project URL` و `anon public` و `service_role`.

### 2) Vercel — متغيرات البيئة (Settings ← Environment Variables)
| الاسم | القيمة |
|---|---|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_ANON_KEY` | anon public |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role (سرّي، لا يوضع في الكود أبدًا) |
| `ALLOWED_EMAILS` | بريدك (ويمكن عدة بريدات مفصولة بفواصل) |
| `GOOGLE_MAPS_API_KEY` | اختياري |

إن لم تُضبط الثلاثة الأولى تُرجع الواجهة البرمجية خطأ 503 ولا تعمل (آمن افتراضيًا).
إن كانت `ALLOWED_EMAILS` فارغة يُرفض الجميع.

### 3) GitHub ثم Vercel
ارفع المشروع إلى مستودع **خاص** على GitHub ثم Vercel ← Add New Project ← اختر المستودع ← Deploy.
(`.gitignore` يمنع رفع `.env` وبيانات المواقع المحلية.)

### التشغيل المحلي بنفس قاعدة Supabase (اختياري)
ضع المتغيرات نفسها في `.env` ثم `npm start`.
